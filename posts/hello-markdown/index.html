这是一篇用于展示博客排版的示例文章，可在发布自己的文章后删除。

写作可以从很小的地方开始：一个问题、一段代码，或者一个暂时没有答案的想法。这篇示例展示博客里常用的排版方式。

给想法一个清晰的结构

用二级标题拆分主要内容，用三级标题补充细节。长文章的目录会从标题自动生成，读者可以跳到自己关心的部分。

一篇技术记录，可以沿着这样的顺序展开：

  1. 问题是什么：先交代背景与目标。
  2. 如何理解它：写下关键假设、推导或实验。
  3. 结果与边界：记录观察，也留下还不确定的地方。

不必等到完全想清楚才开始写。把问题准确地描述出来，本身就是一次进展。

留下可以复现的代码

代码块支持语法高亮和一键复制。下面是一个简单的 Python 示例：

from collections import Counter


def most_common_words(words: list[str], top_k: int = 3):
    """统计单词频率，并返回出现最多的词。"""
    counts = Counter(word.lower() for word in words)
    return counts.most_common(top_k)


print(most_common_words(["Think", "Build", "Write", "think"]))

行内代码也可以用来标记函数，例如 most_common_words()。写代码之外，最好再解释一下输入、输出，以及选择这种实现的原因。

让信息容易比较

适合并列对照的信息，可以放进表格：

内容写作方式适用场景
一个概念定义、例子、边界学习笔记
一次实践问题、过程、结果工程记录
一段思考观察、感受、疑问个人随笔

列表不需要太长，表格也不需要装下所有内容。让段落保持呼吸感，往往比堆满细节更重要。

从这里开始

你可以在 src/content/posts/ 中新建一个 Markdown 文件，填写标题、日期、摘要与分类，再写下正文。

title: '我的第一篇文章'
description: '用一句话介绍这篇文章。'
date: 2026-10-26
category: 技术
tags: ['学习笔记']
draft: false

将 draft 设为 true 可以保留草稿而不公开。文章的日期与分类会显示在首页，标签会出现在归档筛选中。

更多 Markdown 语法可以参考 Markdown Guide。把这篇示例删除后，这里就完全属于你了。
